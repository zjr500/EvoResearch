# 面板拆分时新增的接口设计

本文是前端联调草案，依据接口契约 v1.2 补充页面需要的读回字段和行为。下列推测已配置到前端，业务后端实现前需要相关成员确认。原有 Word 契约保留在仓库中。

## 1. 新增预警规则读取接口

| 项目 | 设计 |
| --- | --- |
| 功能 | F13 预警规则 |
| 方法与路径 | `GET /experiments/{id}/alert-rules` |
| 提供方 | 胡语晨的界面子系统后端 |
| 调用方 | `src/client/features/alerts/api.js` |
| 用途 | 打开预警页面时读回已有规则，编辑后再调用已有 PUT 接口整组保存 |
| 返回 | `{code: 0, message: "ok", data: {rules: [...]}}` |
| 无规则 | 成功返回 `rules: []` |
| 归属 | 按 DSH 当前业务用户检查任务访问权限 |
| 错误 | 不存在或无权访问返回业务码 4004，未登录返回 HTTP 401 |

`rules[]` 的元素沿用 PUT 契约，包含 `rule_id`、`metric`、`direction`、`threshold`、`split`、`repeat_policy`、`channel`、`enabled`。新增的周期字段见下一节。

GET 未成功时，页面显示错误并保留重试入口。规则表单在读取成功后开放，以免把尚未读到的已有规则覆盖为空。

## 2. 在现有规则 GET 和 PUT 中补周期字段

v1.2 有 `repeat_policy=interval`，缺少周期长度。暂定新增 `interval_seconds`，类型为正整数，单位为秒。选择 `interval` 时必填，其他策略下前端省略这个字段。

暂定同一规则第一次命中可以立即提醒，之后至少相隔 `interval_seconds` 秒才能再次提醒。时间和上次通知记录由界面子系统后端维护，以便页面关闭或重新打开后仍按同一周期运行。数据库需补相应字段或等价存储。

当前前端提供周期输入框并发送该字段。重复判定和通知发送等待后端实现。

规则 PUT 继续沿用整组提交、整组生效。草案补充移除语义，已存规则未出现在本次 `rules[]` 中时删除，空数组表示清空。修改在一个事务中生效。前端对清空全部规则显示确认。

## 3. 在知识条目详情中返回备注

功能属于 F4。对已有 `GET /kb/entries/{id}` 的 `data` 增加 `user_note: string | null`。这是从现有 PUT 已允许编辑 `user_note` 推导出的读取字段。

暂定 PUT 省略 `user_note` 时保留原值，传空字符串时清空备注。前端把缺省值显示为空，只有用户改动备注时才发送。张嘉荣确认存储和是否参与向量化，前端不修改 `content` 等生成字段。

## 4. 候选多种子统计字段

第二章 candidates 表已有 `val_metric_mean`、`val_metric_std`、`seed_count`，候选列表字段表仍主要写 `val_metric`。暂定在已有 `GET /experiments/{id}/candidates` 的每个候选中附带这三个可空字段。

前端优先显示 `val_metric_mean`，缺省时使用已有的 `val_metric`；标准差与种子数缺省时显示「—」。没有接到的统计值保持缺省。由马雨瑶确认候选列表的字段。

## 5. 事件 payload 的待确认结构

已有事件接口确定了 `taskId`、`seq`、`type`、`runId`、`step`、`split`、`payload`。目前前端完整显示 `payload`，因此下列字段作为后续细化展示的建议，尚未用于计算或状态判断。

| 事件类型 | 建议的 payload 字段 | 用途 |
| --- | --- | --- |
| log | `message`、`level`、`recorded_at` | 日志文本、错误级别、发生时间 |
| run_status | `status`、`started_at`、`finished_at` | 步骤状态和耗时 |
| decision | `summary`、`basis`、`next_action` | 决策摘要、行动依据和下一步 |
| metric | `name`、`value`、`epoch`、`global_step`、`seed`、`recorded_at` | 指标变化通知 |
| alert | `rule_id`、`metric`、`value`、`threshold`、`message`、`recorded_at` | 预警内容 |
| finish | `status`、`reason`、`recorded_at` | 完成或结束原因 |

SSE 的 `event` 应等于 `data.type`，`id` 应等于 `data.seq`。客户端首次没有历史事件时传 `since=0`，重连同时存在 `since` 和 `Last-Event-ID` 时，服务端优先采用后者。

## 6. 接口挂载和其他假设

默认把契约里的路径挂在 DSH 当前目录下的 `evoresearch/api/`，例如知识库完整路径为 `/evoresearch/api/kb/entries`。这是本地原型的挂载约定，可以在面板的「接口设置」修改同源前缀。

`channel` 暂沿用数据库说明中的中文值「界面弹窗」「邮件」。确认正式枚举后只需修改 F13 表单和适配代码。邮件配置、发送结果和触发判定需要界面子系统后端实现。

所有写请求沿用 `idempotency_key`。同一页面内相同动作和请求内容在失败后重试时复用原键，成功后下一次操作生成新键。切换任务或关闭页面会取消本地等待，后端仍须以幂等键和自身事务保证执行一致性。

现阶段按 DSH 本地单 owner 运行，多个独立部署使用各自的数据。DSH 的浏览器 owner 不能直接区分同一宿主里的多位用户，多用户业务身份仍需团队确定。

## 7. 本次实现范围

普通构建只发实际接口请求。已有业务接口保持 v1.2 的方法和字段大小写，例如知识库使用 `nextCursor`，任务、事件和候选列表使用 `next_cursor`。

## 实验提交和知识图谱预留

这两块沿用接口契约 v1.2，未新增长期业务路由。各自的 `api.js` 可供对应页面接入，但预留页面当前不发请求，也没有提交控件或绘图逻辑。

- 实验提交的草稿定义包含必填 `hypothesis`、`model_plan`、`dataset`、`split_rule`、`train_config`、`target_metric`、`optimization_direction`、`seed_count`。后两项允许 `maximize/minimize` 和正整数，单种子固定为 1，多种子至少为 2。阈值可由后端建议。三个写阶段是创建或修改「待确认」草稿、确认并进入「待启动」、绑定就绪主机后启动。各写请求由公共 API 添加 `idempotency_key`，页面尚未接入主机选择或任何实际执行。
- 图谱的中心条目用 `entryId`。图谱返回节点的 `entry_id` 和边的 `source_entry_id`、`target_entry_id`、`edge_type`、`weight`。节点详情使用 `nodeId`（图谱缓存记录的 ID），不能用 `entry_id` 冒充。v1.2 的图谱列表字段未明确返回 `nodeId`，接入点击详情前要由提供方确认取得它的方式。图谱作业在 `pending/running` 时返回空列表或旧缓存，不能把此时的空结果解释为无关联。

## 本地调试数据

`npm run build:debug` 允许手动切到内存适配器。它沿用现有方法、路径和 JSON 信封，支持知识条目、任务、轮次、历史和本地事件流、指标、候选、认证进度、预警规则和模拟终止。修改只保留在当前页面；模拟终止经「终止确认中」再返回「已终止」，不会触发真实执行。实验提交和图谱仍保持预留。没有新增模拟 HTTP 路由，也不会在真实接口失败时自动切换到样例。

预警规则 GET、周期字段、备注读回与候选统计字段是本次推测。规则判断、预警事件写入、通知和数据持久化由业务后端提供。前端在业务接口未部署时显示错误。真实数据联调需要这些后端就绪。
