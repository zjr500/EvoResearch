# 文档修改规定

适用：2026.11.18 及以后所有版本。评审或开发中发现的问题，都按这份规定处理。

## 一、问题分三类，分类定处理

| 类别 | 什么样的问题 | 怎么处理 |
| --- | --- | --- |
| A 类：内容矛盾 | 契约内部两处说法不一致，或契约与需求规格、数据库设计对不上。照着写代码会出两种实现 | **立即修**。修完四人同步确认 |
| B 类：缺口待补 | 契约还没写到、后续功能才需要的接口或字段 | **记入待补充清单，不立即修**。谁的功能先用到谁提出，由接口提供方在该功能开发前补进契约 |
| C 类：文档瑕疵 | 接口数量统计、题注、错别字这类纯文档问题，照着写代码不会出错 | **不单独修**。下次因 A 类或 B 类改文档时顺带改 |

## 二、封面日期与版本

每个文档封面写两项：**报告日期**＝首次定稿的年月（如"报告日期：2026年10月（原始立项）"），定稿后不再改；**当前版本**＝版本号＋当次修订日期（如"当前版本：v3.0（2026年11月18日）"），每次修订时更新。
