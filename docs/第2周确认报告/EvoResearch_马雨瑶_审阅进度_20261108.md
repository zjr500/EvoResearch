## 已完成的调研

- 对照领域类图和文字说明，梳理 ResearchTask、ExperimentRun、ExperimentEvent、MetricRecord、Candidate、RemoteHost 的归属与重数，核对任务从“待确认”到“已完成”的状态边界。
- 交叉核查用例清单、顺序图消息与操作契约：UC05 的校验结果只有 valid 和 thresholdSuggestion，下一步却需要 confirmTask(taskId)；UC07 返回 hostId，但 UC05—UC07 尚无明确的任务与主机绑定消息。

## 最小可行性验证

- 用标准库脚本读取源 DOCX，核出 13 个用例、8 个任务状态；UC05—UC07 的契约数为 2＋4＋2＝8 份，全组为 23 份，与工作量表中的 7 份、22 份不符。
- 按契约搭建简化状态机，演练启动失败不创建轮次、修复后重试、认证中断后只处理未认证候选、终止指令未确认时保持“终止确认中”；断言均通过。
- 输入输出链检查发现 returnValidation 未提供 taskId；UC05—UC07 的消息均未同时包含 taskId 和 hostId，任务与主机的关联无法由现有消息直接建立。
- 验证边界：脚本只检验文档一致性和状态规则样例，尚未运行插件、数据库或真实 GPU 远程实验。
