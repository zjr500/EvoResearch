## 公共入口与数据库

- `src/index.ts` 调用 `src/runtime.ts`，只安装现有知识库模块；无 SSH import 或迁移执行。
- `src/infrastructure/database.ts` 统一路径、连接、外键、busy timeout 和关闭；知识库模块接受共享连接，不自行打开数据库。
- `EVORESEARCH_DB_PATH` 未设时保持原来的 `data/evoresearch.sqlite`；相对路径基于进程工作目录。推荐绝对路径，避免从不同目录启动产生不同数据库。
- PDF 目录仍是数据库旁的 `papers/`，不移动已有文件。
- `src/infrastructure/migrations.ts` 用事务调度现有知识库迁移；保留 `knowledge_migrations`，以 `evoresearch_migrations(module,version,applied_at)` 记录本批已接管版本。
- 不修改原 SQL、不转换 `knowledge_operations`、不新建共享 `operation_records`。旧 papers 数据及 ID 保留，已部署知识库 v2 不重放 SQL。
- 未识别的 kb_entries 或更新版本迁移记录会拒绝启动并回滚，要求显式核对；不会自动覆盖。
- 当前迁移登记只接管 knowledge v2，后续接入新模块必须注册迁移并补测试，不能直接在共享登记表插入任意版本。
- 停用时先注销路由、等待已有知识库任务结束，再关闭连接。单个插件实例共享一条连接，非跨进程连接池。
- DSH owner 认证、REST 路径、默认模型继承及单任务模型快照保持不变；未引入凭证管理。

## 安装和运行

使用既有 Node.js 22.23.5 与 DSH 0.2.1-rc.2。根锁文件和前端锁文件均保持原版本；F12 统一使用根目录已锁定的 TypeScript。

```powershell
npm ci
npm ci --prefix modules/frontend
npm run check
npm run build
npm test
# 使用自己的绝对路径；不要指向尚未备份的生产数据库做验收
$env:EVORESEARCH_DB_PATH = 'C:\your-local-validation\evoresearch.sqlite'
npm run db:migrate
npm run db:migrate
# 将已构建项目安装至独立 DSH Web profile 后，从同一环境启动
dsh plugin --profile evoresearch-integration add .
dsh --profile evoresearch-integration --no-open
```

DSH profile 需包含既有 base 和 web-app bundle。环境模板不自动加载，必须由启动进程显式设置。前端组件构建产物仍独立，不自动覆盖 DSH 布局。无需安装 F7 依赖。
