通过 `ctx.get('evoresearchModels')` 获取 `PurposeModels`：

```ts
const models = ctx.get('evoresearchModels');
// 未给 choice 时分别读取 SUMMARY 或 EXPERIMENT 成对覆盖；否则继承 DSH 默认。
const selected = models.selection('experiment', { mode: 'dsh-default' });
const other = models.selection('summary', {
  mode: 'selected', provider: 'already-configured-provider', model: 'configured-model'
});
// 自主实验将来可直接传给原生 Agent，不创建第二套 Agent。
// ctx.agents.create({ sessionId, meta: { cwd }, agentOptions: selected });
```

- `selection` 返回单次不可变快照，保留 reasoningEffort；`stream(purpose,request,choice)` 委托 `ctx.llm.stream`，不实现 Provider。
- `directory()` 返回原生已配置 provider 与可配置 provider 的 `settingsNs`；`models(provider)` 委托原生模型目录。用户新增 provider/key 应在 DSH 原生对应模型设置中完成，再选择其 provider/model。公共服务不接受、存储或输出 API Key，也不代替 DSH 配置编辑器。
- 新增可选 `EVORESEARCH_EXPERIMENT_PROVIDER/MODEL`。summary 和 experiment 独立覆盖；显式 `dsh-default` 可忽略用途覆盖；半配置报错。

## 本地执行公共能力

`ctx.get('evoresearchLocalExecution')` 提供受信任插件后端调用，不暴露任意执行 REST。

- `startPython(owner,key,{python,cwd,script,args?,sessionId?})`：使用第二批幂等服务，返回 operation_id；通过 `lookup(owner,operation_id)` 获得稳定 execution_id 和 DSH job_id。
- `status/output/stop`：复用 DSH jobs 的查询、偏移读取及 kill；另外等待 subprocess 的管理范围退出，才返回 terminationConfirmed。
- `checkEnvironment(owner,key,{python,cwd,sessionId?})`：运行仓库内只读环境脚本，检查 CPU、Python、nvidia-smi、PyTorch/TensorFlow 安装与框架 GPU 可用性。结果经原生输出流读取。
- 公共调用者必须从 DSH 可信上下文取得 owner/sessionId，不允许从客户端任意透传归属。sessionId 为已有原生 Agent 时，任务由 DSH session fence 管理；无 session 的内部任务使用 DSH unowned job，本机 owner 是当前权限边界。
- subprocess 负责执行、输出收集和进程树终止；jobs 负责后台 ID、输出 ring、状态和会话归属；fs 负责路径解析；sandbox.confine 包装 argv。没有另写 shell、SSH、进程树扫描器或后台队列。
- 默认仅 `workspace-write`，原生 sandbox 不可用则失败，不自动降级到无限制执行。
- 新增 `local_executions` 迁移和 `local-execution:1` 登记。只存执行标识、操作关联、owner/session、job_id、状态、退出码与停止确认，无凭证或训练业务数据。
- 手动停止的 native job 状态为 killed；共享操作沿用四状态，记为失败、error='Local execution stopped'，避免把停止误认作训练成功。
- 不能证明进程树退出时，状态为 unknown、termination_confirmed=0，仍保留当前进程内 handle 供清理重试，不宣称停止成功。
- 宿主重启后保留 execution_id 和历史记录，但原生 job/handle 不可重建，未完成记录标记 unknown，不自动恢复或重复执行。原生输出 ring 为有界运行期数据，不保证重启后读取完整日志。
- 保持一个数据库对应一个活跃 DSH 宿主。未实现完整自主实验循环、训练指标协议、业务审批动作或远程执行。

### 测试集隔离结论：不满足读取隔离

DSH 返回 enforcement=partial。模拟 train/validation 在工作目录，test.txt 在相邻 heldout 目录，存在 test.lock：

- Python 读取 train/validation：成功。
- 通过 `../heldout/test.txt` 读取测试集：成功。
- 通过绝对路径读取测试集：成功。
- 向 heldout/test.txt 追加写入：被拒绝，数据未改变。

这与固定版本 `dsh-sandbox-windows-acl/README.md` 的 WRITE_RESTRICTED 说明一致：写限制不是读隔离。目录分离和锁文件只是协作约定，不能阻止 Python 直接读取。访问日志由验收控制器记录已知尝试，不是不可绕过的 OS 审计。

保留独立目录、锁文件及访问日志设计，但不得据此宣称测试集对 Agent 代码保密。在选定经验证的读取隔离方案前，不应将真实保密测试集放到不受信任训练代码可读的同一用户文件空间。本批未引入 Docker、WSL、额外账号或复杂安全架构。
