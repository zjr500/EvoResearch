# UC01 后端实现与验收

## 依据与范围

业务依据为仓库内《EvoResearch_需求分析.pdf》（UC01，正文第11–14页，PDF第12–15页）。PDF 字体映射导致提取乱码，已渲染核对原页。本说明记录必要变更，不改正式需求文档。

保留用户已有 003 迁移、pending_summary、先摘要再确认实现及有效测试调整；修正其并发、迁移、路由及调用方遗漏。没有修改 DSH、Node、依赖锁文件、共享操作记录实现、其他成员模块或前端。本轮不涉及 Docker。

## 逐条验收

| UC01 项目 | 后端实现与实际证据 | 边界 |
|---|---|---|
| 配置摘要模型或复用已有配置 | DSH 模型目录/默认选择；按 owner 的默认知识库保存用途选择；失败不覆盖旧值；任务内固定模型和 reasoningEffort | 不存 API Key；新增凭证仍在 DSH 原生设置。目录校验不等于远程凭证连通验证 |
| 一篇或多篇上传 | 逐篇 `POST /papers`，客户端汇总各 operation；真实 PDF 解析，SHA256 按 owner 去重；不同论文可以独立成功或失败 | 不新增 multipart/大数组上传；每个 PDF 20 MiB，整体 JSON 28 MiB |
| 解析论文及生成摘要 | 新上传在同一异步操作中解析后调用现有 DSH stream 适配器；原文 abstract 与 AI summary 分开 | 本轮模型为 Mock；解析缺失字段允许人工补齐，没有假造作者/年份 |
| 提供待确认信息 | `GET /papers/{id}` 返回原始 abstract、结构化 summary、状态、revision；KB 查询不含待确认论文 | 文件路径、全文及内部运行令牌不返回 |
| 修改论文或摘要 | PATCH 带 expected_revision；允许 title/authors/year/abstract/summary，限制归属与字段 | PUT 的旧确认语义暂保留，避免悄悄解释为编辑 |
| 重新生成 | 显式 POST summary，新幂等键才发起新尝试；并发同论文只允许一个模型执行；失败保留旧有效摘要 | 中断不自动重放付费调用；没有后台自动重试 |
| 确认后入库 | 非空标题 + 有效 AI 草稿；事务同时改变状态、创建唯一 KB 条目、写发布事件；失败全部回滚 | 未确认或取消操作的论文保持待确认，不创建条目 |
| 展示多篇入库结果 | batch confirm 返回逐篇 paper_id/code/paper 或错误；成功项不被失败项回滚 | 批次操作“成功”表示处理完毕，调用方仍须检查每项 code |
| 关联知识与索引同步 | 确认时原子写入 durable publication；公开查询服务可按 owner/cursor 读取；详情显示 pending | 尚无索引/图谱消费者，不声称已建立关系或完成语义检索；UC01 完整业务后置条件中的关系建立仍待 UC02/03 接入 |

## 数据库

- 保留 `003_pending_summary.sql`，新增 `004_uc01.sql`。统一迁移登记 knowledge 2/3/4、operations 1、local-execution 1，共5项；重复迁移不重放。
- papers 新增 revision、summary_status（not_generated/running/ready/failed）、summary_error、summary_run、legacy_status。pending_summary 保存未确认 AI 摘要 JSON；abstract 始终是原文/用户修订的原始摘要。
- 每次编辑、解析结果及摘要成功都推进 revision；summary_run 防止跨请求重复执行。模型返回后检查 revision，防止覆盖用户在执行期间的修订。失败仅更新生成状态/安全错误，不覆盖有效摘要。
- 旧版“已入库”且确有 KB 条目的论文保持原状；“已入库”但从未创建 KB 条目的论文转待确认，同时 legacy_status 记录旧状态。保留 paper_id、原文路径、元数据、旧操作 ID/结果，不删除任何已有数据。已有 v3 AI 草稿也保留。
- knowledge_model_choices 只存 owner、选择 JSON、revision，不存凭证；当前对应单 owner 的默认知识库，不扩展多库管理。
- knowledge_sync_events 保存 document_id、owner_id、entry_revision、event_type、index_status/graph_status 和时间；已有 KB 条目回填 pending 事件。没有伪造索引成功记录。
- 正式数据升级前应备份 SQLite 与 papers 目录。本轮只升级自动化临时库及独立验收库，未动已有真实论文数据库。

## API 与旧契约冲突

所有变更请求仍带 idempotency_key，返回 HTTP 202 和现有 OperationService 操作形状，轮询 `/kb/operations/{id}` 获取业务结果；`/operations/{id}` 公共查询保持不变。认证仍由 DSH connection.admit 实施，本机 owner=1；测试中的不同 owner 用于验证存储/服务隔离，不代表部署了多用户登录。

| 路径 | 约定 |
|---|---|
| GET /models?purpose=summary | DSH providers/configurable（含原生 settingsNs）及当前保存选择；本轮仅 summary |
| GET /models/{provider} | DSH 模型目录；`summary` 路径保留给配置资源 |
| GET /models/summary | `{choice,revision}`；choice=null 表示没有保存覆盖，沿用环境变量/DSH 默认逻辑 |
| PUT /models/summary | `{idempotency_key,model_choice,expected_revision}`；先目录校验，再 CAS 保存；不可用时保留原配置 |
| POST /papers | `{idempotency_key,pdf_base64,model_choice?}`；新上传解析并生成待确认摘要；重复上传不重复调用模型 |
| GET /papers/{id} | 论文元数据、原始 abstract、pending_summary/summary 对象、revision、summary_status/error、document_id（确认前 null） |
| PATCH /papers/{id} | `{idempotency_key,expected_revision,title?,authors?,year?,abstract?,summary?}`；兼容 pending_summary 别名，不能同时传两个摘要字段 |
| POST /papers/{id}/summary | `{idempotency_key,model_choice?}`；仅待确认论文，结果为 paper_id/status/summary/pending_summary/revision，不再返回 document_id |
| POST /papers/confirm | `{idempotency_key,paper_ids:[...],expected_revisions:{"1":2,...}}`；1–100个不重复 ID；逐篇短事务、逐篇结果 |
| PUT /papers/{id} | 保留历史“确认”入口；现在必须有有效 AI 摘要并携带 expected_revision；新调用方用 PATCH 编辑、batch confirm 确认 |
| GET /kb/entries、/{id} | 已有列表/详情兼容；详情新增 index_status/graph_status，未同步返回 pending |

model_choice 为 `{mode:'dsh-default'}` 或 `{mode:'selected',provider,model,reasoningEffort?}`。显式 dsh-default 优先于旧环境变量；无保存选择和请求覆盖时，保留现有成对环境变量覆盖/默认继承逻辑。配置内容白名单拒绝 apiKey 等字段，模型/目录异常使用固定错误消息；不把底层错误或凭证放入操作结果。

必要兼容性变化：

1. 历史 F1/F2 的“确认 → 生成摘要 → 创建 KB”违反新版 UC01，改为“上传生成草稿 → 检查/修改 → 确认创建 KB”。旧历史验收记录未改写。
2. 现有实现把 PUT /papers/{id} 用作确认而非编辑。本轮保留旧语义，明确新增 PATCH；不得让前端继续用 PUT 保存未确认编辑。
3. 旧摘要结果中的 document_id/source_id/content 不再适用于草稿结果；只有确认结果及 paper 详情才给正式 document_id。不能返回虚假的条目 ID 来保持表面兼容。
4. PATCH、单篇确认与批量确认需要客户端携带读取时的 revision；过时提交返回4009，重新读取再确认。相同幂等键的重放返回原操作，不重新执行。
5. 无效文件不创建论文；可识别 PDF 头但解析失败时保留可修复记录。再次上传同一坏文件仍返回解析失败；可补全标题/摘要后显式请求生成。模型失败保留解析结果并提示重试；重复上传本身不自动产生新付费请求。
6. 修改无全文论文的原始 abstract 会失效其旧 AI 草稿，需重新生成；不能在确认请求中悄悄更换原始摘要并沿用旧 AI 摘要。

## 后续模块衔接

- 公共同进程服务 `evoresearchKnowledgePublications.list(owner, afterEventId?, limit?)`：读取已确认条目的持久发布事件。事件与确认事务同生共死；consumer 用 event_id/document_id/entry_revision 做幂等，按 owner 读取业务条目，不能把 pending 当完成。
- UC02 可复用 papers/KB ID、paperView、entryFor/listEntries、revision、OperationService、知识库模型选择与现有认证。正式编辑/删除条目的版本事件及索引失效处理仍由 UC02 实现；本轮没有补做这些业务。
- UC03 可消费 publication 并建立真实关系，更新其同步状态；未实现消费者/确认回执 API，不允许直接跨模块任意写表。正式消费者接入时需补充共享服务写接口及错误/重试测试。
- 对其他成员影响限于新增迁移、`/models` 路由、知识库调用顺序及返回字段。F7/F12/前端源码未改动；全量回归包括现有 dialogue 与 frontend 测试。正式前端目前仅有 KB 浏览等调用，未发现正式论文上传调用；历史临时验收页面不进入本次提交。
