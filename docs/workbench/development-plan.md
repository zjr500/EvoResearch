# EvoResearch 统一工作台开发与验收计划

2026-10-26；第五阶段为有条件验收。原始单次配对结果持平且测试集略差于基线，保留全部证据，不作为知识增强有效性的证明。

## P0：本机可操作工作台与 DSH Web 联调

- 使用 DSH 0.2.1-rc.3 的 sidebar.panellist/main 插槽挂载页面，复用 DSH 会话、工具注册与运行时；不开发第二套聊天系统。
- 按科研项目组织文献、检索问答、任务配置、进度、候选结果、知识回流与图谱。
- 后端复用第五阶段真实 AutoResearch/MLflow/Graphiti；补项目目录、列表查询、重试与安全的浏览器访问。
- 用户必须能创建项目、提交/停止任务、查看双状态、比较同模板结果、检索来源、将证据送到 DSH 会话。
- 验收：真实 DSH Web 页面操作、后端集成测试、启动/停止/健康检查及隔离环境复现记录。失败、空数据、离线状态不得展示模拟成功。

## P1：Zotero 接入与个人环境体验

- 支持 Zotero CSL JSON 导入、Web API v3 只读分页接入；以版本/内容哈希保持幂等。无摘要条目保留明确跳过原因，不虚构全文。
- 私有文献库真实验收需要用户提供库类型、ID、密钥文件路径，密钥仅留在服务端。
- 接入实现测试与用户真实库验收分开记录；没有凭据不宣称真实库通过。
- 在用户本机启动 DSH、API、实验 Worker、投影 Worker，提供明确日志和停止入口，收集体验问题。

## P2：多任务知识增强收益评估

- 覆盖时间序列预测、分类、回归；每类多个独立任务/数据划分，增强/无增强成对运行。
- 对齐初始代码、数据、种子、预算、模型配置；冻结来源，隔离对照，禁止最终测试指标进入规划。
- 记录实验预算、实际调用 tokens、检索/知识准备额外消耗；报告逐对差值与分布，负结果同样保留。
- 区分功能闭环与收益证明，不将 Ridge 确定性求解的重复 seed 计作独立样本。
- 大批量真实 API 评估在工作台稳定后执行；本轮不预填未执行的多任务收益。

## 最终端到端验收门槛

新目录安装 → 配置密钥/Neo4j → DSH Web 登录 → 项目 → Zotero 文献 → 可见检索 → 实验 → MLflow → Graphiti → 后续实验引用，保存操作记录、版本、配置哈希和来源链。
阶段报告逐项列“已通过 / 待环境 / 待执行”，不能以离线 mock 替代 Zotero、DSH Web 或真实模型证据。
